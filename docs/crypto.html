⚠️ Important Disclaimer

Do not use this web app to encrypt secrets.

Although we do not use cookies and do not collect any data, using a web application for encrypting sensitive information is fundamentally insecure and not recommended.

While the encryption algorithm itself is cryptographically sound, the JavaScript environment is not secure enough for protecting important secrets. Browser JavaScript can be compromised, intercepted, or modified in transit.

For any important purposes:

  • Use a native implementation (desktop/CLI tools)
  • Follow the security recommendations in their official documentation
  • Never trust web-based encryption for sensitive data

This webapp is provided for educational and convenience purposes only. For security usage with sensitive data, use proper cryptographic tools, read documentation from relevant libraries that may implement this algorithm, and follow best practices for secure encryption.

The Algorithm

This is a Secure HMAC-Keyed Block-Based Multi-String Encryption Algorithm. It is designed to securely encrypt multiple strings with separate keys, while producing a single indistinguishable encrypted blob. Each string is padded, tagged, encrypted, and shuffled together, so that no information about the original strings or their keys can be inferred from the encrypted data.

Encryption takes n strings and n keys, pads each string into fixed-size blocks, tags each block with a secret marker derived from its key and position, encrypts every block, then shuffles them all together into one indistinguishable blob. Decryption scans the entire blob with a given key, silently discarding every block that fails authentication, and uses the recovered position indices to reassemble the original string. No block reveals which string it belongs to, and no key grants any foothold into another string's blocks.

The algorithm is intended to provide a means for secure information distribution and plausible deniability, where multiple parties can be given different keys to access only the information they are authorized for, without revealing the structure or existence of other information.

Technical information: 

- Key Derivation: HKDF-SHA256, unsalted
- Block Tagging: HMAC-SHA256 with HMAC subkey
- Encryption: AES-256-GCM with encryption subkey, 96-bit nonce, 128-bit tag
- Padding: PKCS#7 to 64-byte blocks
- Randomization: Fisher-Yates shuffle with crypto.getRandomValues()
- Resulting Block Size: 124 bytes
